# 日本版UI/UXプロダクトガイドライン

日本の「ものづくり」精神（引き算の美学・裏勝り・すり合わせ・おもてなし）をデジタルプロダクトに落とし込むための制作規範。AIが出力しがちな「欧米標準の平均的テンプレート」を避け、日本語と日本のユーザー心理に最適化されたUIを作る。

## 適用タイミング

- 日本語を含むWebサイト・LP・アプリのUIを**新規に作る**とき（実装開始前に本ガイドラインを踏まえる）
- 既存UIを日本市場向けにローカライズ・改善するとき
- ユーザーが「日本人向け」「AIっぽくしないで」「ちゃんとしたサイトに」と言ったとき

レビューが目的の場合は `migiee-ui-ux-check` を使う（本スキルは制作時の規範、あちらは検収時のチェック）。

## 設計思想（判断に迷ったらここに戻る）

1. **引き算の美学** — 装飾を足すのではなく、余分を削いで本質を残す。ただし「余白で誤魔化す」のとは違う（後述の情報密度参照）。
2. **裏勝り** — 見えない部分にこそ手を入れる。エッジケース、エラー系、ローディング、レイアウトシフト対策は「後回し」にしない。
3. **慮（おもんぱか）り** — ユーザーが言葉にしない迷い・躊躇・警戒心を先回りして解消する。
4. **すり合わせ** — コンポーネントを機械的に並べるのではなく、文脈に合わせてピクセル単位・1文字単位で調律する。

## 1. タイポグラフィ（体験の根幹）

| 項目 | 規定 |
|---|---|
| 本文フォント | Noto Sans JP、ヒラギノ角ゴ等の視認性重視の書体。**Inter等の欧文フォントを日本語に当てない** |
| font-family指定 | 和文フォントを先頭に、欧文フォールバックを後ろに（`"Noto Sans JP", sans-serif`） |
| 本文サイズ | 15〜16px（漢字の画数密度を考慮。14px以下は不可） |
| 行間（本文） | line-height 1.6〜1.8（欧文基準の1.4〜1.5は日本語では息苦しい） |
| 見出し行間 | 1.2〜1.4 |
| 字間 | 見出しに letter-spacing 0.02〜0.05em を検討。本文は0〜0.03em |
| 和欧混植 | 英数字と和文のベースラインずれに注意。数字は等幅または欧文フォント指定も可 |
| 約物 | 連続する括弧・句読点の字詰め（`font-feature-settings: "palt"` は見出し限定で検討） |
| 折り返し | `overflow-wrap: break-word` と `word-break: normal`、可能なら `line-break: strict`。不自然な改行位置を防ぐ |
| 長文の禁則 | 1行あたり全角35〜45文字を目安に max-width を設定 |

## 2. 色彩設計

- **純黒 #000000 をテキストに使わない**。チャコールグレー（#1a1a1a〜#333333）を基本とする
- 背景は真っ白 #ffffff よりも、温かみのあるオフホワイト（#fafaf8、#f7f6f3 など）を優先検討
- メインカラーは**彩度を抑えた信頼感のある色**（ネイビー #1e3a5f 系、深緑、えんじ等）。日本の伝統色・くすみカラー（ニュアンスカラー）と相性が良い
- **サイバーなグラデーション（紫→ピンク、青→シアン）をデフォルトで使わない**。AI生成UIの典型パターンであり、日本の一般ユーザーには軽薄・不信の印象を与えやすい
- 60:30:10（ベース:メイン:アクセント）の配分を守る

## 3. コンポーネントの造形

- 角丸は **2〜8px の繊細な値**（12px超の大きな角丸はカジュアル用途に限定）
- 階層表現は**過剰なドロップシャドウではなく、1pxの淡いボーダー**（#e5e5e5 前後）で秩序立てる
- シャドウを使う場合は `0 1px 3px rgba(0,0,0,0.06)` 程度の控えめな値
- 巨大なHero画像＋広大な余白で「それっぽく」構成しない。ファーストビューで「何のサービスで、何ができて、次に何をすべきか」が伝わること

## 4. 情報密度と心理的安全性

日本のユーザーは契約・決済・個人情報入力に対して「騙されたくない」「損をしたくない」という強い警戒心を持つ。抽象的な洗練より**安心感のある具体性**を優先する。

- 必要な情報（料金、送料、期限、条件）は隠さず一目で把握できる密度で提示する
- ステータスはバッジ・タグで明示（「送料無料」「あと3点」「本人確認済み」等）
- **決済・契約・削除など不可逆な操作の前には必ず確認ステップを挟む**
- 価格表示は税込を主、内訳を併記
- 運営者情報・問い合わせ先への導線を分かりやすく置く（信頼担保）

## 5. 「慮り」のフォーム設計

- 入力例をあらかじめ提示する：「半角数字・ハイフンなし（例：09012345678）」
- 全角/半角は**システム側で自動変換**し、ユーザーに入力し直させない
- 姓名・フリガナ・郵便番号→住所自動補完など、日本の慣習に沿ったフィールド構成
- 必須/任意を明示（必須だけ赤アスタリスクではなく「必須」「任意」ラベルを推奨）
- リアルタイムバリデーションは入力完了後（blur時）に。入力中に赤く責めない

### エラーメッセージの文体

**ユーザーを責めず、次の行動を優しく導く。** 直訳調・突き放し調は不信感の元。

| NG（直訳調） | OK（慮り） |
|---|---|
| 「無効な入力です」 | 「メールアドレスの形式をご確認ください（例：name@example.com）」 |
| 「エラーが発生しました」 | 「申し訳ございません。時間をおいて再度お試しください。解決しない場合は〜」 |
| 「パスワードが違います」 | 「メールアドレスまたはパスワードが正しくありません。お忘れの場合はこちら」 |

マイクロコピー全般：命令形より依頼形（「入力してください」→「ご入力ください」）。ただし過剰な敬語で冗長にしない。

## 6. 見えない品質（裏勝り）

- **レイアウトシフト（CLS）の撲滅**：画像・埋め込みに width/height を必ず明示。Webフォント読み込みは `font-display: swap` + サイズ調整
- ローディング・空状態・エラー状態・オフライン時の表示を最初から設計する（「動いて当たり前」への応答）
- 応答性：ボタン押下への即時フィードバック（150〜300msのトランジション）
- 日本語フォントは重い。Noto Sans JPはサブセット化 or `display=swap` のGoogle Fonts経由で最適化

## 7. AI生成UIの典型パターン矯正チェック

実装後、以下に該当していないか自己点検する（該当したら修正）：

- [ ] Interや system-ui だけで日本語を表示していないか
- [ ] line-height が1.5以下になっていないか
- [ ] 紫〜ピンクのグラデーション、意味のないぼかし玉（blob）を置いていないか
- [ ] 巨大Hero＋薄い内容の「見た目だけLP」になっていないか
- [ ] 角丸16px超・大ぶりシャドウの「ふわふわカード」を量産していないか
- [ ] エラー文言が直訳調・機械的になっていないか
- [ ] 料金・条件などユーザーが不安に思う情報を「すっきり見せるため」に隠していないか
- [ ] 確認ステップなしで決済・送信が完了してしまわないか

## 出力時の振る舞い

- 実装時は上記の数値をデフォルト値として採用し、逸脱する場合は理由をユーザーに一言添える
- ユーザーのブランドカラーやトンマナ指定がある場合はそれを優先しつつ、本ガイドラインの原則（可読性・心理的安全性）は維持する
- 完成後、セクション7のチェックを実施し、必要なら `migiee-ui-ux-check` での本格レビューを提案する
