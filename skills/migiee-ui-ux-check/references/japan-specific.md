# 日本向けサイトの追加チェック観点

対象が日本語UI・日本市場向けサイトの場合、SKILL.md本体の4軸に加えてここを確認する。

## タイポグラフィ

### フォント選定チェック
| 場面 | 推奨 | NGパターン |
|---|---|---|
| 行政・金融・医療・公共性 | Noto Sans JP | — |
| コーポレート（汎用） | 游ゴシック／ヒラギノ角ゴ | — |
| アプリ・SaaS UI | Noto Sans JP／LINE Seed JP | — |
| 親しみ・toC・子ども向け | M PLUS Rounded 1c／ZEN Maru Gothic | 硬いゴシックのみで温かみがない |
| 高級・伝統・和 | 見出しのみ明朝体 | **本文に明朝体を使っている（画面上で横線が消えて可読性が下がる）** |
| データ・数値 | 数字だけInter/Roboto Mono指定 | 和文フォントの数字で表がガタつく |

**チェックすべき典型的な失敗**：
- 本文が明朝体になっている → ゴシックに変更を指摘
- 本文がLight/Thinウェイトになっている → 漢字の線が潰れる。Regular以上を指摘
- 大文字化やイタリックで強調しようとしている → 日本語には効かない。サイズ・色・余白で強調すべきと指摘
- 和欧混植で游ゴシックとNoto Sans JPなど太さ・字面の異なるフォントが混在している

### 数値
- 行間（本文）：欧文基準の1.5がそのまま使われていないか確認。**日本語は1.7〜1.8を推奨**（デジタル庁デザインシステム基準：行ボックス高さをフォントサイズの1.5倍以上、実務は1.7〜1.8）
- 段落間：行ボックス高さの1.5倍以上（フォントサイズの2.25倍以上）
- 行長：全角40文字程度が目安（半角80文字相当）。ただし情報の網羅性を優先すべきコンテンツもあるため機械的に適用しない
- `letter-spacing`：本文0〜0.04em。詰めすぎ注意。大見出しのみ-0.02em程度で締める
- `text-align: justify` が日本語に使われていないか（字間が不自然に開くため基本NG）
- 見出しの改行位置：意味のかたまりを無視した機械的な折り返しになっていないか（`<wbr>`や`word-break: keep-all`、手動改行での制御を推奨）
- 英数字が全角になっていないか（半角が基本、全角混在は素人っぽく見える）

### フォント実装
- サブセット化されているか（日本語フォントは数MBになりCore Web VitalsのLCPを直撃する）
- 見出しWebフォント／本文デバイスフォントのハイブリッド構成になっているか
- `font-display`とpreloadが設定されているか
- フォールバックフォントが日本語用に適切に並んでいるか（`"Noto Sans JP", "Hiragino Sans", "Hiragino Kaku Gothic ProN", "Yu Gothic", Meiryo, sans-serif` 等）

## 色

日本市場では色の含意が欧米と異なる場合がある。特に以下は指摘対象。

- **赤をエラー色と販促色で兼用している**：日本では赤は「セール・お得・緊急・祝い」など多義的。エラー表示と販促バナーが同じ赤だと意味が混線する。彩度や文脈で明確に分離すべき
- 暖色（赤・橙・黄）＝購買促進、寒色（青・緑・紫）＝信頼構築、という使い分けができているか。BtoB/SaaSでEC的な暖色配色になっていないか（安っぽく見える）
- 4・9をプラン数・階数・価格末尾で使っていないか（特に医療・不動産・冠婚葬祭）
- 白黒のみの配色（弔事を想起させる可能性がある構成）になっていないか

## レイアウト・情報密度

日本のユーザー行動は「情報を減らす」ことが必ずしも正解ではない、という前提でチェックする。

| ターゲット | 推奨密度 | チェック観点 |
|---|---|---|
| 一般消費者EC・比較サイト・不動産・求人 | 高密度が正解 | 余白を取りすぎて「情報が足りない＝不安」になっていないか。角丸4〜8px |
| BtoB SaaS・スタートアップ | 中〜低密度 | 海外標準に寄せてよい。角丸12〜16px |
| 高齢者向け・行政 | 中密度＋大きめ文字 | 18px以上、1画面1タスクになっているか |
| Z世代向けアプリ | 低密度・大胆な余白 | — |

「日本＝ごちゃごちゃで良い」でも「海外ミニマルが常に正解」でもない。**情報を削るのではなく、階層化して畳む**（アコーディオン、タブ、段階開示）ができているかを見る。特に比較検討型の商材（保険・不動産・BtoB）で欧米風の余白過多なミニマルLPになっている場合は要注意——情報不足に見えてCVが落ちる典型パターン。

## フォーム（最重要・離脱に直結）

日本のフォームは実装の手間が離脱率に直結する。以下が未実装ならHigh〜Medium相当で指摘する。

- [ ] 郵便番号→住所自動入力があるか（`autocomplete="postal-code"`、ハイフン有無どちらでもエラーにならないか）
- [ ] フリガナ自動入力があるか（漢字氏名入力時にひらがな/カタカナを自動補完）
- [ ] 全角/半角の自動変換があるか（「半角で入力してください」というエラー表示は設計の敗北と見なす）
- [ ] `inputmode`が項目ごとに適切か（電話番号→numeric、メール→email等）でスマホのキーボードが最適化されているか
- [ ] 都道府県はセレクトボックスになっているか（47件、順序が統一されているか）
- [ ] 氏名が姓・名の2フィールドになっているか（日本標準。ただし外国人ユーザー配慮の1フィールド化も文脈次第で許容）
- [ ] 必須項目が「※」だけでなく「必須」バッジ等で文字表記されているか
- [ ] EC/決済ならクレカ以外の決済手段（コンビニ払い・代引き・キャリア決済・コード決済・後払い）があるか
- [ ] 配送日時指定があるか（日本では標準機能として期待される）

## この観点でのレポート追加例

```
### 🟡 Medium（日本市場向け）
- [フォーム] 郵便番号からの住所自動入力が実装されていない
  → 郵便番号APIと連携し、7桁入力で都道府県〜町域まで自動補完する
- [タイポグラフィ] 本文の行間が1.5（欧文基準）のまま
  → 日本語は1.7〜1.8を推奨。line-heightを1.7に変更
```
