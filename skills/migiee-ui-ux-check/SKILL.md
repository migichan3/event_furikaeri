# UI/UXチェック

Webサイト・LP構築のセルフチェック用Skill。実装中〜納品前に、感覚ではなく基準でレビューする。

## 使うタイミング

- コード（HTML/CSS/React等）、画像/スクリーンショット、Figma、または稼働中のURLを渡された
- 「レビューして」「これで大丈夫？」「AIっぽく見えない？」「もっと良くするには？」と聞かれた
- ユーザー自身がWeb UIを作っている最中で、区切りが良いタイミング

対象がない/曖昧な場合は、何をレビューしたいか（コード貼り付け・画像・URL）を一つだけ確認してから進める。

## 進め方

1. **対象を把握する** — コードなら実際のCSSの値（px, color, font-family等）を読む。画像/URLなら視覚的に確認する。既存のスクリーンショット撮影・ブラウザ確認手段があれば使う。
2. **4軸で機械的にチェックする**（詳細は下記の各セクション、深掘りが必要なら references/ を読む）
3. **severity付きでレポートする**（下記フォーマット）。指摘は「基準のどの数値/原則に違反しているか」を必ず添える。感想ではなく根拠を示す。
4. **直し方を1〜2行で添える**。ダメ出しだけで終わらせない。
5. 指摘が多い場合、**severity Highのみ先に見せて**、残りは「他にも◯件あります、見ますか」と聞く。一度に大量の指摘を流し込まない。

## 5つのチェック軸

### 軸1：認知の法則（普遍・崩れない）
- ヤコブの法則：既知のUIパターンから逸脱しすぎていないか（ロゴ位置、ナビ、カート等）
- ヒックの法則：1画面の主要CTAは1つか。メニューは多すぎないか
- フィッツの法則：重要ボタンは十分大きく、押しやすい位置か
- ミラーの法則：フォーム・情報は4±1のチャンクに分かれているか
- ゲシュタルト（近接）：関連要素は罫線より余白でグルーピングされているか
- ニールセンの10ヒューリスティックス、特に：状態の可視化、Undo可能性、エラー予防＞エラーメッセージ

### 軸2：数値の鉄則
実測値をコードから拾って基準と照合する。以下を満たさない場合は具体的な差分（例："14px → 16px以上に"）を示す。

| 項目 | 基準 |
|---|---|
| スペーシング | 8ptグリッド（4,8,12,16,24,32,48,64） |
| 本文フォントサイズ | 16px以上（日本語は16〜17px） |
| 行間（本文） | 欧文1.5〜1.75 / **日本語1.7〜1.8** |
| 行間（見出し） | 1.1〜1.3 |
| 型スケール比率 | 1.25倍 or 1.333倍、サイズ種類5〜7個まで |
| 色比率 | 60:30:10（ベース:メイン:アクセント） |
| コントラスト比 | 通常テキスト4.5:1以上／大きな文字(24px以上 or 太字18.5px以上)は3:1以上／UIコンポーネント・アイコンも3:1以上 |
| タップ領域 | 44×44px以上（WCAG最低基準は24×24pxだが実務は44px） |
| モーション時間 | UIトランジション150〜300ms |
| LCP / INP / CLS | 2.5秒未満 / 200ms未満 / 0.1未満（実ユーザーの75パーセンタイル基準） |
| 画像・埋め込み | 全てにwidth/height明示（CLS対策） |

Web検索で最新のWCAG/Core Web Vitals基準に変更がないか確認したい場合は検索して良い（基準は年単位で更新される）。

### 軸3：プラットフォーム規約・トークン設計
- コンポーネントは default / hover / focus / active / disabled / loading / error / empty の状態を持っているか
- 色はセマンティック命名になっているか（`blue-500`ではなく`color-action-primary`）
- 空・エラー・ローディング状態が後回しにされていないか
- `prefers-reduced-motion` を尊重しているか、キーボードフォーカスリングが消されていないか
- iOS/Android向けなら Liquid Glass / Material 3 Expressive の作法（詳細は references/universal-principles.md）

### 軸5：ブランドの仕上げ（favicon・アイコン）
実装の最終段階で忘れられがちだが、「作り込まれている感」に直結するため必ず確認する。

- favicon が設定されているか。フレームワークのデフォルト（Vite/Next.jsのロゴ、真っ白/透明の1x1等）のまま放置されていないか
- ブラウザタブ・ブックマーク・スマホのホーム画面追加（Apple touch icon / Android manifest icon）まで一式揃っているか
- favicon がブランドカラー・ロゴと一貫しているか（サイト本体と無関係な色・形になっていないか）
- OGP画像（SNSシェア時のサムネイル）が設定されているか。これも忘れられやすい「仕上げ」の一部

**対象がコード/URLで、favicon関連の実装が確認できる場合**：上記が未実装・デフォルトのままであれば、指摘として必ず拾う（severity: 見た目上の大きな破綻ではないが未完成感に直結するため通常Medium）。まだ何も作られていない/検討段階の場合は、「favicon・アイコンもこのタイミングで作っておくと仕上がりが締まる」と一言添えて提案する。作成を頼まれた場合は、サイトのブランドカラー・ロゴ・世界観に合わせたfaviconのデザイン案を出す（複数サイズ: 16x16, 32x32, apple-touch-icon 180x180, さらにOGP画像1200x630も必要に応じて）。

### 軸4：AIスロップ（AIっぽさ）
詳細は `references/ai-slop-checklist.md`。特に頻出の以下だけは必ず見る：
- 紫→青グラデーション、全カード共通のグレー1px枠線
- 3列カードの単純反復（緩急のないセクション構成）
- 見出しがInter/Robotoのままになっていないか
- 「〜を実現します」「〜ではないでしょうか」等のAI特有言い回しが本文コピーに残っていないか
- ダミーデータ・意味のない装飾ライン・過剰な絵文字アイコン

シルエットテスト（画面を200px幅・白黒・ブロックのみに縮小して競合と見分けがつくか）が有効。可能なら実施を提案する。

**重要な区別**：「硬い」「Claudeっぽい」という指摘は、装飾過多ではなく**装飾を削りきったことによる硬さ**が原因のことが多い。モダンデザインの本質は「装飾ゼロ」ではなく「機能美と洗練の両立＋ブランド文脈の反映」。無彩色＋グレーのみ、角丸が全て同一値、柔らかい装飾要素がゼロ、モーションが皆無——これらは「引き算しすぎたAIスロップ」であり、`references/modern-vs-rigid.md` の基準で見直す。

## 日本向けサイトの場合

対象が日本語UI/日本市場向けなら `references/japan-specific.md` を読んで追加チェックする。特に以下は見落とされがち：
- 本文が明朝体・Lightウェイトになっていないか（画面上で線が消える）
- 行間が欧文基準（1.5）のままになっていないか
- フォームに郵便番号自動入力・フリガナ自動入力・全角半角自動変換があるか
- 色の使い方が「赤＝エラーと販促を兼用」になっていないか
- 情報密度がターゲット層に対して適切か（比較検討型商材で余白過多になっていないか）

## レポート出力フォーマット

```
## UI/UXチェック結果

### 🔴 High（必須修正）
- [軸/項目] 具体的な指摘（実測値 → 基準値）
  → 直し方

### 🟡 Medium（推奨修正）
- ...

### 🟢 Good（良い点、簡潔に）
- ...

### 総評
1〜2文で、このUIの一番の課題と一番の強みを言う。
```

- Highは「基準を明確に割っているもの」「ユーザーがタスクを完了できなくなるもの」のみに絞る。何でもHighにしない。
- Goodは社交辞令ではなく、実際に基準を満たしている/意図的な良い判断をしている箇所を挙げる。何もなければ書かない。
- 全部で10件を超える指摘がある場合は、severity Highと「最初に直すべき3つ」を優先して見せる。
